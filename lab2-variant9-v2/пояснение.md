## 3. Чистая архитектура — как устроен проект

Проект разбит на слои-«кожурки» (луковая архитектура). Внутренние слои ничего не знают о внешних:

```
API (контроллеры)            ← принимает HTTP-запросы, отдаёт JSON
      ↓
Application (сервис)         ← бизнес-логика: проверки, лимит 50, покупка
      ↓
Domain (модель)              ← сущность Product — ничего не знает ни о ком
      ↑
Infrastructure (репозиторий) ← «база данных» = список в памяти
```

Схема папок:

```
lab2-variant9/
├── pom.xml                                     ← список зависимостей
└── src/main/
    ├── java/com/example/store/
    │   ├── StoreApplication.java               ← старт программы
    │   ├── domain/Product.java                 ← модель товара
    │   ├── domain/ProductRepository.java       ← интерфейс хранилища (контракт)
    │   ├── application/ProductService.java     ← бизнес-логика
    │   ├── application/exceptions/             ← ошибки бизнес-логики
    │   ├── infrastructure/InMemoryProductRepository.java ← реализация хранилища в памяти
    │   └── api/                                ← веб-слой (контроллер + обработчик ошибок + DTO)
    └── resources/
        ├── application.properties              ← настройки (порт)
        └── static/                             ← HTML-страницы магазина
```

    }

    public void setBrand(String brand) {
        this.brand = brand;

        this.price = price;

### 4.4. Хранилище: интерфейс `domain/ProductRepository.java` и реализация `infrastructure/InMemoryProductRepository.java`

Хранилище состоит из **двух** файлов. Интерфейс лежит во внутреннем слое `domain`, а реализация —
во внешнем `infrastructure`. Это центральное правило чистой архитектуры: внутренний слой (сервис)
зависит от абстракции (интерфейса), а не от конкретного класса-хранилища.

Интерфейс `domain/ProductRepository.java`:

```java
package com.example.store.domain;

import java.util.List;
import java.util.Optional;

public interface ProductRepository {

    List<Product> findAll();

    Optional<Product> findById(int id);

    Product save(Product product);

    boolean update(Product product);

    boolean delete(int id);

    int count();
}
```

**Пояснение.** Интерфейс — это «контракт»: он описывает, какие операции нужны от хранилища, но не
говорит, как они устроены. Сервису всё равно, где хранятся данные — в списке, в файле или в базе:
он видит только этот контракт.

Реализация `infrastructure/InMemoryProductRepository.java`:

```java
package com.example.store.infrastructure;

import com.example.store.domain.Product;
import com.example.store.domain.ProductRepository;
import org.springframework.stereotype.Repository;

import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

@Repository
public class InMemoryProductRepository implements ProductRepository {

    private final List<Product> products = new ArrayList<>();
    private int nextId = 1;

    @Override
    public synchronized List<Product> findAll() {
        return new ArrayList<>(products);
    }

    @Override
    public synchronized Optional<Product> findById(int id) {
        return products.stream()
                .filter(product -> product.getId() == id)
                .findFirst();
    }

    @Override
    public synchronized Product save(Product product) {
        product.setId(nextId++);
        products.add(product);
        return product;
    }

    @Override
    public synchronized boolean update(Product product) {
        for (int i = 0; i < products.size(); i++) {
            if (products.get(i).getId() == product.getId()) {
                products.set(i, product);
                return true;
            }
        }
        return false;
    }

    @Override
    public synchronized boolean delete(int id) {
        return products.removeIf(product -> product.getId() == id);
    }

    @Override
    public synchronized int count() {
        return products.size();
    }
}
```

**Пояснение.** Это и есть «база данных» — обычный список `ArrayList` в оперативной памяти
(как и требует задание: «хранилище реализовать в памяти»). Данные живут, пока работает сервер.
- `implements ProductRepository` — класс обещает выполнить все методы интерфейса.
- `@Override` — подтверждение, что метод переопределён из интерфейса.
- `@Repository` — пометка для Spring: «когда сервис попросит хранилище — дай именно этот класс».
- `nextId` — счётчик для выдачи новых id (1, 2, 3…); `synchronized` — защита от одновременных запросов.
- `findAll` возвращает **копию** списка, чтобы хранилище нельзя было случайно изменить извне.
- Если завтра понадобится настоящая база данных, пишется новый класс `implements ProductRepository`,
  а сервис и остальной код **не меняются ни строчки**.

### 4.5. `application/ProductService.java` — бизнес-логика

```java
package com.example.store.application;

import com.example.store.application.exceptions.LimitExceededException;
import com.example.store.application.exceptions.NotEnoughStockException;
import com.example.store.application.exceptions.NotFoundException;
import com.example.store.application.exceptions.ValidationException;
import com.example.store.domain.Product;
import com.example.store.domain.ProductRepository;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class ProductService {

    public static final int MAX_PRODUCTS = 50;

    private final ProductRepository repository;

    public ProductService(ProductRepository repository) {
        this.repository = repository;
    }

    public List<Product> getAll() {
        return repository.findAll();
    }

    public Product getById(int id) {
        return repository.findById(id)
                .orElseThrow(() -> new NotFoundException("Товар не найден"));
    }

    public Product create(Product product) {
        validate(product);

        if (repository.count() >= MAX_PRODUCTS) {
            throw new LimitExceededException("Достигнут лимит товаров: " + MAX_PRODUCTS);
        }

        return repository.save(product);
    }

    public Product update(int id, Product product) {
        getById(id);
        validate(product);

        product.setId(id);
        repository.update(product);
        return repository.findById(id).orElseThrow();
    }

    public void delete(int id) {
        if (!repository.delete(id)) {
            throw new NotFoundException("Товар не найден");
        }
    }

    public Product buy(int id, int quantity) {
        if (quantity <= 0) {
            throw new ValidationException("Количество должно быть больше нуля");
        }

        Product product = getById(id);

        if (product.getCountInStock() < quantity) {
            throw new NotEnoughStockException(
                    "Недостаточно товара на складе: доступно " + product.getCountInStock() + " шт.");
        }

        product.setCountInStock(product.getCountInStock() - quantity);
        repository.update(product);
        return product;
    }

    private void validate(Product product) {
        if (product.getName() == null || product.getName().isBlank()) {
            throw new ValidationException("Поле name обязательно");
        }
        if (product.getBrand() == null || product.getBrand().isBlank()) {
            throw new ValidationException("Поле brand обязательно");
        }
        if (product.getPrice() <= 0) {
            throw new ValidationException("Цена должна быть больше нуля");
        }
        if (product.getCountInStock() < 0) {
            throw new ValidationException("Количество на складе не может быть отрицательным");
        }
    }
}
```

**Пояснение.** Здесь живут все **правила магазина**, а не «голое» сохранение данных:
- `MAX_PRODUCTS = 50` — лимит из задания; при попытке добавить 51-й товар выбрасывается ошибка.
- `validate` — проверка полей: имя и бренд не пустые, цена больше нуля, количество не отрицательное.
- `create` — сначала проверяет данные, потом лимит, только затем сохраняет.
- `update` — сначала убеждается, что товар существует, проверяет поля и сохраняет под тем же id.
- `buy` — логика покупки: количество должно быть положительным, товар должен существовать,
  и **нельзя купить больше, чем есть на складе**; если всё хорошо — уменьшает `countInStock`.
- `@Service` и конструктор — Spring сам передаёт сюда репозиторий (это и есть внедрение зависимостей).
- Вместо возврата «строки ошибки» сервис **выбрасывает исключения** (например `NotEnoughStockException`) —
  веб-слой ловит их и превращает в нормальный HTTP-ответ.

### 4.7. `api/dto/ProductRequest.java` — форма запроса на создание/изменение

```java
package com.example.store.api.dto;

import com.example.store.domain.Product;

public record ProductRequest(String name, String brand, double price, int countInStock) {

    public Product toProduct() {
        Product product = new Product();
        product.setName(name);
        product.setBrand(brand);
        product.setPrice(price);
        product.setCountInStock(countInStock);
        return product;
    }
}
```

**Пояснение.** DTO (Data Transfer Object) — отдельная «форма», в которой приходят данные из браузера.
`record` — короткая запись класса в Java (сам создаёт конструктор и геттеры). Главное отличие от `Product`:
здесь **нет id** — id всегда выдаёт сервер, пользователь его не присылает. Метод `toProduct()` превращает
форму в настоящую модель.

### 4.8. `api/dto/PurchaseRequest.java` и `api/dto/ProductResponse.java` — DTO покупки и ответа

```java
package com.example.store.api.dto;

public record PurchaseRequest(int quantity) {
}
```

**Пояснение.** Для покупки браузер присылает только количество: `{"quantity": 2}`. Этого достаточно.

Отдельный DTO для **ответа** сервера:

```java
package com.example.store.api.dto;

import com.example.store.domain.Product;

public record ProductResponse(int id, String name, String brand, double price, int countInStock) {

    public static ProductResponse from(Product product) {
        return new ProductResponse(
                product.getId(),
                product.getName(),
                product.getBrand(),
                product.getPrice(),
                product.getCountInStock()
        );
    }
}
```

**Пояснение.** `ProductResponse` — «публичный вид» товара для браузера. Он похож на доменную модель,
но это **другой** класс из слоя `api`, и управляется только веб-слоем:
- у `ProductResponse` есть `id` (браузеру он нужен для ссылок), а у `ProductRequest` id нет — его выдаёт сервер;
- статический метод `from(Product)` превращает доменную модель в DTO;
- если завтра в модели `Product` появятся служебные поля (например, внутренний флаг), наружу они
  не утечут — в JSON попадут только поля `ProductResponse`.

Таким образом, у DTO своя задача: `ProductRequest` — что **принимаем** (без id),
`ProductResponse` — что **отдаём** (с id). Тип «входа» и «выхода» эволюционируют независимо друг от друга.

### 4.9. `api/ProductController.java` — контроллер (веб-слой)

```java
package com.example.store.api;

import com.example.store.application.ProductService;
import com.example.store.api.dto.ProductRequest;
import com.example.store.api.dto.ProductResponse;
import com.example.store.api.dto.PurchaseRequest;
import com.example.store.domain.Product;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.net.URI;
import java.util.List;

@RestController
@RequestMapping("/api/products")
@Tag(name = "Products", description = "CRUD магазина электроники. Хранилище в памяти, лимит 50 товаров.")
public class ProductController {

    private final ProductService service;

    public ProductController(ProductService service) {
        this.service = service;
    }

    @GetMapping
    @Operation(summary = "Получить список всех товаров")
    public List<ProductResponse> getAll() {
        return service.getAll().stream()
                .map(ProductResponse::from)
                .toList();
    }

    @GetMapping("/{id}")
    @Operation(summary = "Получить товар по id")
    public ProductResponse getById(@PathVariable int id) {
        return ProductResponse.from(service.getById(id));
    }

    @PostMapping
    @Operation(summary = "Добавить товар",
            description = "Возвращает 201 Created. Лимит магазина — 50 товаров.")
    public ResponseEntity<ProductResponse> create(@RequestBody ProductRequest request) {
        Product created = service.create(request.toProduct());
        return ResponseEntity
                .created(URI.create("/api/products/" + created.getId()))
                .body(ProductResponse.from(created));
    }

    @PutMapping("/{id}")
    @Operation(summary = "Обновить товар по id",
            description = "Полностью заменяет name, brand, price, countInStock.")
    public ProductResponse update(@PathVariable int id, @RequestBody ProductRequest request) {
        return ProductResponse.from(service.update(id, request.toProduct()));
    }

    @DeleteMapping("/{id}")
    @Operation(summary = "Удалить товар по id",
            description = "Возвращает 204 No Content.")
    public ResponseEntity<Void> delete(@PathVariable int id) {
        service.delete(id);
        return ResponseEntity.noContent().build();
    }

    @PostMapping("/{id}/purchase")
    @Operation(summary = "Купить товар",
            description = "Уменьшает countInStock. Нельзя купить больше, чем есть на складе.")
    public ProductResponse buy(@PathVariable int id, @RequestBody PurchaseRequest request) {
        return ProductResponse.from(service.buy(id, request.quantity()));
    }
}
```

**Пояснение.** Контроллер — «приёмная» приложения: он принимает HTTP-запросы и решает, какой метод
сервиса вызвать. Сам он ничего не считает — вся логика в `ProductService`.
Входящие данные он превращает из DTO в доменную модель (`request.toProduct()`), а исходящие — обратно
(`ProductResponse.from(...)`): наружу доменная модель не уходит.
- `@RestController` — класс отдаёт JSON-ответы.
- `@RequestMapping("/api/products")` — все адреса начинаются с `/api/products`.
- `@GetMapping` / `@PostMapping` / `@PutMapping` / `@DeleteMapping` — какой HTTP-метод обслуживает метод Java.
- `@PathVariable int id` — берёт id прямо из адреса (`/api/products/5` → id = 5).
- `@RequestBody` — превращает присланный JSON в объект DTO.
- Наружу возвращается не доменная модель `Product`, а DTO `ProductResponse` (через `ProductResponse.from(...)`) — веб-слой не «светит» внутренней моделью.
- `@Operation` и `@Tag` — это описания для **Swagger** (обязательное требование задания).
- `create` дополнительно возвращает код **201 Created** и адрес созданного товара (правила REST).
- `delete` возвращает **204 No Content** — «успешно, но отвечать нечем».
- Покупка сделана отдельным эндпоинтом `POST /api/products/{id}/purchase` — это действие, поэтому POST.

### 4.10. `api/GlobalExceptionHandler.java` — обработчик ошибок

```java
package com.example.store.api;

import com.example.store.application.exceptions.LimitExceededException;
import com.example.store.application.exceptions.NotFoundException;
import com.example.store.application.exceptions.NotEnoughStockException;
import com.example.store.application.exceptions.ValidationException;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.Map;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(NotFoundException.class)
    public ResponseEntity<Map<String, String>> handleNotFound(NotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body(Map.of("error", ex.getMessage()));
    }

    @ExceptionHandler(ValidationException.class)
    public ResponseEntity<Map<String, String>> handleValidation(ValidationException ex) {
        return ResponseEntity.badRequest()
                .body(Map.of("error", ex.getMessage()));
    }

    @ExceptionHandler(LimitExceededException.class)
    public ResponseEntity<Map<String, String>> handleLimit(LimitExceededException ex) {
        return ResponseEntity.badRequest()
                .body(Map.of("error", ex.getMessage()));
    }

    @ExceptionHandler(NotEnoughStockException.class)
    public ResponseEntity<Map<String, String>> handleStock(NotEnoughStockException ex) {
        return ResponseEntity.badRequest()
                .body(Map.of("error", ex.getMessage()));
    }
}
```

**Пояснение.** Этот класс ловит ошибки из сервиса, чтобы сервер не «падал», а отвечал аккуратным JSON.
- `@RestControllerAdvice` — «слушай ошибки во всех контроллерах».
- `@ExceptionHandler(...)` — какой тип ошибки обрабатывает метод.
- `NotFoundException` → код **404**; ошибки валидации, лимита и склада → код **400**.
- Все ответы в едином виде: `{"error": "текст ошибки"}` — именно это сообщение потом показывает страница в браузере.

#### `static/app.js` — скрипт всех страниц

```javascript
function el(tag, className, text) {
    var node = document.createElement(tag);
    if (className) {
        node.className = className;
    }
    if (text !== undefined) {
        node.textContent = text;
    }
    return node;
}

function showMessage(text, isError) {
    var box = document.getElementById("message");
    if (!box) {
        return;
    }
    box.textContent = text;
    box.className = isError ? "error" : (text ? "success" : "");
}

function apiRequest(path, options) {
    return fetch(path, Object.assign({
        headers: { "Content-Type": "application/json" }
    }, options || {})).then(function (response) {
        if (response.status === 204) {
            return null;
        }
        return response.json().catch(function () {
            return null;
        }).then(function (data) {
            if (!response.ok) {
                throw new Error((data && data.error) || "Ошибка запроса");
            }
            return data;
        });
    });
}

function getProducts() {
    return apiRequest("/api/products");
}

function getProductById(id) {
    return apiRequest("/api/products/" + id);
}

function createProduct(product) {
    return apiRequest("/api/products", {
        method: "POST",
        body: JSON.stringify(product)
    });
}

function updateProduct(id, product) {
    return apiRequest("/api/products/" + id, {
        method: "PUT",
        body: JSON.stringify(product)
    });
}

function deleteProduct(id) {
    return apiRequest("/api/products/" + id, {
        method: "DELETE"
    });
}

function buyProduct(id, quantity) {
    return apiRequest("/api/products/" + id + "/purchase", {
        method: "POST",
        body: JSON.stringify({ quantity: quantity })
    });
}

function productInfo(item) {
    return "Цена: " + item.price + " | На складе: " + item.countInStock + " шт.";
}

function loadProductList(container) {
    getProducts().then(function (products) {
        container.textContent = "";

        if (products.length === 0) {
            container.appendChild(el("p", "", "Товаров пока нет. Добавьте первый на странице «Добавить»."));
            return;
        }

        products.forEach(function (item) {
            var article = el("article", "product-item");
            article.appendChild(el("h2", "", item.id + ". " + item.name));
            article.appendChild(el("p", "brand", item.brand));
            article.appendChild(el("p", "", productInfo(item)));

            var link = el("a", "", "Изменить");
            link.href = "edit.html?id=" + item.id;
            article.appendChild(link);

            container.appendChild(article);
        });
    }).catch(function (err) {
        container.textContent = "";
        container.appendChild(el("p", "error", err.message));
    });
}

function loadDeleteList(container) {
    getProducts().then(function (products) {
        container.textContent = "";

        if (products.length === 0) {
            container.appendChild(el("p", "", "Товаров нет — удалять нечего."));
            return;
        }

        var list = el("ul", "delete-list");

        products.forEach(function (item) {
            var row = el("li");
            var label = el("span");
            label.appendChild(el("strong", "", item.name));
            label.appendChild(document.createTextNode(" — " + item.brand + " (" + productInfo(item) + ")"));
            row.appendChild(label);

            var button = el("button", "", "Удалить");
            button.addEventListener("click", function () {
                button.disabled = true;
                deleteProduct(item.id).then(function () {
                    row.remove();
                    showMessage("Товар удалён.", false);
                }).catch(function (err) {
                    button.disabled = false;
                    showMessage(err.message, true);
                });
            });
            row.appendChild(button);

            list.appendChild(row);
        });

        container.appendChild(list);
    }).catch(function (err) {
        container.textContent = "";
        container.appendChild(el("p", "error", err.message));
    });
}

function initAddForm(form) {
    form.addEventListener("submit", function (event) {
        event.preventDefault();
        showMessage("", false);

        createProduct({
            name: document.getElementById("name").value,
            brand: document.getElementById("brand").value,
            price: parseFloat(document.getElementById("price").value),
            countInStock: parseInt(document.getElementById("countInStock").value, 10)
        }).then(function () {
            window.location.href = "index.html";
        }).catch(function (err) {
            showMessage(err.message, true);
        });
    });
}

function initEditForm(form) {
    var id = new URLSearchParams(window.location.search).get("id");
    var nameInput = document.getElementById("name");
    var brandInput = document.getElementById("brand");
    var priceInput = document.getElementById("price");
    var stockInput = document.getElementById("countInStock");
    var submitButton = form.querySelector("button[type='submit']");

    if (!id) {
        showMessage("Не указан id товара в адресе страницы.", true);
        submitButton.disabled = true;
        return;
    }

    getProductById(id).then(function (item) {
        nameInput.value = item.name;
        brandInput.value = item.brand;
        priceInput.value = item.price;
        stockInput.value = item.countInStock;
    }).catch(function (err) {
        showMessage(err.message, true);
        submitButton.disabled = true;
        return;
    });

    form.addEventListener("submit", function (event) {
        event.preventDefault();
        showMessage("", false);

        updateProduct(id, {
            name: nameInput.value,
            brand: brandInput.value,
            price: parseFloat(priceInput.value),
            countInStock: parseInt(stockInput.value, 10)
        }).then(function () {
            window.location.href = "index.html";
        }).catch(function (err) {
            showMessage(err.message, true);
        });
    });
}

function refreshProductSelect() {
    var select = document.getElementById("productSelect");

    return getProducts().then(function (products) {
        select.textContent = "";

        if (products.length === 0) {
            var emptyOption = document.createElement("option");
            emptyOption.value = "";
            emptyOption.textContent = "Нет товаров — добавьте на странице «Добавить»";
            select.appendChild(emptyOption);
            return;
        }

        products.forEach(function (item) {
            var option = document.createElement("option");
            option.value = item.id;
            option.textContent = item.id + " — " + item.name + " (" + item.brand + "), в наличии: " + item.countInStock + " шт.";
            select.appendChild(option);
        });
    });
}

function initBuyPage(form) {
    var select = document.getElementById("productSelect");
    var quantityInput = document.getElementById("quantity");

    refreshProductSelect().catch(function (err) {
        showMessage(err.message, true);
    });

    form.addEventListener("submit", function (event) {
        event.preventDefault();
        showMessage("", false);

        if (!select.value) {
            showMessage("Сначала добавьте товар на странице «Добавить».", true);
            return;
        }

        var quantity = parseInt(quantityInput.value, 10);
        if (isNaN(quantity) || quantity <= 0) {
            showMessage("Количество должно быть целым числом больше нуля.", true);
            return;
        }

        buyProduct(select.value, quantity).then(function (product) {
            showMessage("Покупка оформлена: " + product.name + ". Осталось на складе " + product.countInStock + " шт.", false);
            return refreshProductSelect();
        }).catch(function (err) {
            showMessage(err.message, true);
        });
    });
}

window.onload = function () {
    var productList = document.getElementById("productList");
    var deleteList = document.getElementById("deleteList");
    var addForm = document.getElementById("addForm");
    var editForm = document.getElementById("editForm");
    var buyForm = document.getElementById("buyForm");

    if (productList) {
        loadProductList(productList);
    }
    if (deleteList) {
        loadDeleteList(deleteList);
    }
    if (addForm) {
        initAddForm(addForm);
    }
    if (editForm) {
        initEditForm(editForm);
    }
    if (buyForm) {
        initBuyPage(buyForm);
    }
};
```

**Пояснение.** Один скрипт обслуживает все страницы. При загрузке `window.onload` смотрит, какие
элементы есть на текущей странице, и включает только нужную логику:
- `apiRequest` — общая функция запроса к серверу. Она отправляет `fetch`, а если сервер вернул ошибку
  (с `{"error": ...}`), превращает её в исключение с текстом — этот текст потом видит пользователь.
- `getProducts` / `createProduct` / `updateProduct` / `deleteProduct` / `buyProduct` — «обёртки» над
  эндпоинтами (GET / POST / PUT / DELETE / покупка).
- `loadProductList` — рисует каталог; `loadDeleteList` — список с кнопками удаления.
- `initAddForm` и `initEditForm` — перехватывают отправку формы (`preventDefault`), отправляют данные
  и переводят на каталог.
- `initBuyPage` + `refreshProductSelect` — заполняют список товаров и оформляют покупку.
- `el()` — маленький помощник, создающий элемент страницы, чтобы не писать много кода.
- **Важно:** при создании элементов используется `textContent`, а не HTML-вставка — это защищает от
  подстановки вредоносного кода через названия товаров.

2. Дождаться, пока IDEA подтянет зависимости (нужен интернет).
3. Запустить `StoreApplication.java` (зелёная кнопка ▶).
4. Открыть в браузере:
   - **Страницы магазина:** `http://localhost:8080`
   - **Swagger UI:** `http://localhost:8080/swagger-ui.html`

Сборка возможна и из терминала (если установлен Maven):
`mvn spring-boot:run`

## 6. Эндпоинты API (они же — в Swagger)

| Метод | Адрес | Что делает | Ответ |
|---|---|---|---|
| GET | `/api/products` | список всех товаров | 200 + массив |
| GET | `/api/products/{id}` | один товар по id | 200 или 404 |
| POST | `/api/products` | добавить товар | 201 + созданный товар |
| PUT | `/api/products/{id}` | изменить товар | 200 + изменённый товар |
| DELETE | `/api/products/{id}` | удалить товар | 204 или 404 |
| POST | `/api/products/{id}/purchase` | купить товар (уменьшает остаток) | 200 или 400 (если не хватает) |

Пример тела запроса для POST/PUT:

```json
{
  "name": "iPhone 15",
  "brand": "Apple",
  "price": 79990,
  "countInStock": 5
}
```

## 8. Возможные вопросы на защите

**— Где тут чистая архитектура?**
Код разбит на четыре слоя: `api` (контроллеры и DTO), `application` (бизнес-логика),
`domain` (модель и интерфейс хранилища), `infrastructure` (реализация хранилища).
Внутренние слои не знают о внешних: сервис зависит только от интерфейса `ProductRepository`,
а не от класса-реализации, а контроллер отдаёт наружу DTO `ProductResponse`, а не доменную модель.

**— Зачем нужен интерфейс `ProductRepository`, если реализация всё равно одна?**
Это ключевое правило чистой архитектуры: внутренний слой зависит от абстракции, а не от конкретики.
Сервису всё равно, где лежат данные. Если завтра хранилище станет настоящей базой данных, мы просто
напишем новый класс `DatabaseProductRepository implements ProductRepository` и подключим его —
сервис и вся остальная логика останутся без единого изменения.

**— Почему контроллер возвращает `ProductResponse`, а не сам `Product`?**
Чтобы веб-слой не зависел от внутренней модели и чтобы наружу не утекли служебные поля. У `Product`
могут появиться поля, которые нельзя отдавать клиенту, а JSON должен соответствовать документации
Swagger. `ProductResponse` — это «публичный вид» товара; связывает их метод `ProductResponse.from(product)`.

**— Нужны ли отдельные DTO для создания, обновления и ответа?**
Идеал — три отдельных DTO (`CreateRequest`, `UpdateRequest`, `Response`), потому что со временем они
расходятся: в запросе на обновление может быть id, у создания — нет; у ответа — своя логика.
В нашей лабе создание и обновление принимают одинаковый набор полей, поэтому один `ProductRequest`
допустим, а ответ отличается (есть id) — для него и сделан отдельный `ProductResponse`.
Правило: поля совпадают — можно переиспользовать DTO; разошлись — разделять.

**— Почему хранилище просто в памяти, а не база данных?**
Так написано в задании: «Хранилище реализовать в памяти». Поэтому роль базы выполняет список в
классе `InMemoryProductRepository`. Если понадобится настоящая БД, меняется только этот один класс
(точнее — добавляется новый, реализующий тот же интерфейс), остальной код не трогается
(это и есть польза слоистой архитектуры).

**— Где реализован лимит 50?**
В `ProductService`: константа `MAX_PRODUCTS = 50` и проверка в методе `create`.

**— Где PUT?**
`PUT /api/products/{id}` в контроллере и страница `edit.html` на фронтенде.

**— Как работает Swagger?**
Библиотека springdoc сама читает аннотации `@GetMapping`, `@Operation` и строит страницу
`/swagger-ui.html`, где видны все эндпоинты и можно отправить тестовый запрос прямо из браузера.
